Is brute force the best you can do?

For a quarter of a century, computer scientists assumed that some puzzles can never be solved much faster than by trying everything. In October 2026, two AI labs posted proofs that this assumption, the Exponential Time Hypothesis, is false. Here is what it said, how the new algorithm works, and why your computer will not notice.

Status, mid-November 2026: a claimed result, not yet peer-reviewed. An independent review led by Russell Impagliazzo, Ramamohan Paturi and Ryan Williams is under way; this page will be updated when it reports.

Symbol glossary: every symbol on this page, in the order it appears
x1, x3, x4
Variables. Each one is set to true or false.
∨
“or”. (x1 ∨ x4) holds if at least one of x1, x4 is true.
¬
“not”. ¬x3 is true exactly when x3 is false.
( … ∨ … ∨ … )
A clause: terms joined by “or”. In 3-SAT each clause has at most three terms, and every clause must hold at once.
3-SAT
The question “can every clause be made true at the same time?” for formulas with at most three terms per clause. k-SAT allows k terms.
n
The number of variables.
2n
The number of ways to set n true/false switches: each new variable doubles it. 250 is about 1015.
1.3n
The best running time known before 2026. Still exponential, just with a smaller base than 2.
c
A fixed positive number, however small. 2cn means “exponential, at some fixed rate”: 1.3n is 20.38n.
ETH
Exponential Time Hypothesis (Impagliazzo and Paturi, 1999): there is some c > 0 for which every 3-SAT algorithm needs at least 2cn steps on some formulas.
SETH
Strong ETH: as clauses get wider, the best possible base climbs all the way to 2. In symbols, for every ε > 0 there is a width k where k-SAT cannot be done in 2(1−ε)n steps. SETH implies ETH, so refuting ETH refutes SETH too.
T
The dial in Kintali’s version of the proof. T = 0 is the original formula; certain whole-number T make it fall apart into small groups.
polynomial in T
A sum like 3 + 2T − 5T2: whole powers of T, each times a fixed number. A few values (and derivatives) fix all the coefficients, so they also fix its value at T = 0. That is interpolation.
log n
The logarithm: how many times you double 1 to reach n. It grows very slowly: log 1,000,000 ≈ 20.
log log n
The logarithm taken twice, slower still: for n = 1,000,000 it is about 4.3.
√
Square root. √log n grows even more slowly than log n, but faster than log log n.
2n·log log n/√log n
The new running time. The exponent is n divided by √log n / log log n, a factor that keeps growing, so eventually the exponent falls below cn for every fixed c.
2o(n)
“Subexponential”. The little o means the exponent grows more slowly than any fixed fraction of n. This is exactly what ETH said could not happen.
C
The hidden constant multiplying the new exponent: the real bound is about 2C·n·log log n/√log n. Nobody knows its value, and it decides when the new method finally wins.
1032
1 followed by 32 zeros. For scale, the observable universe has about 1080 atoms.
polynomial time, polynomial memory
Growing like n2, n3 or nk for some fixed k: the kind of growth computers can live with.
P, NP
P: problems solvable in polynomial time. NP: problems whose answers can be checked in polynomial time. 3-SAT is in NP, and is as hard as anything in it. P = NP would need 3-SAT in polynomial time, far beyond this result.
Lean
A proof assistant: software that checks every step of a formal proof mechanically.

The puzzle at the bottom of it all

A 3-SAT formula is a list of clauses like (x1 ∨ ¬x3 ∨ x4): “x1 is true, or x3 is false, or x4 is true.” You must choose true or false for every variable so that every clause holds. The zebra puzzle and the river crossing can both be written this way, and so, with some effort, can almost any search problem.

With n variables there are 2n assignments to try. Cleverer algorithms beat that, but only by shrinking the 2: the best known before 2026 ran in about 1.3n steps. The Exponential Time Hypothesis, stated by Impagliazzo and Paturi in 1999, said that is all anyone will ever manage: some fixed c > 0 makes every algorithm take at least 2cn steps. A whole field of “this cannot be done faster” results was built on it.

Counting by algebra

The new algorithm does not search. It counts the solutions exactly, and a count of zero means there are none. The starting point is a classic identity: turn each clause into a polynomial that equals 1 when the clause holds and 0 when it fails. Multiply every clause’s polynomial together and the product is 1 on a solution and 0 everywhere else. Add it up over all assignments and you have the count.

That sum still has 2n terms. But if the clauses fell into separate groups that share no variables, you could count each group on its own and multiply, which is enormously cheaper. Try Two separate groups above. Real formulas are tangled, so the trick is to untangle them on purpose.

Untangling with a dial

In Shiva Kintali’s simplified version of OpenAI’s proof, every variable inside the clause polynomials is replaced by a mixture of variables controlled by a dial T. At T = 0 nothing changes, so the sum still gives the true count. At certain whole-number settings of T the formula falls apart into small groups, joined only through a few integer “measurements”: sums of variables with small integer weights. Fix the measurements’ values, and each group can be summed alone.

Those whole-number settings give the wrong numbers, sometimes negative or fractional, but that does not matter. The total is a polynomial in T, so its values and a few of its derivatives at the settings that are easy to compute pin down its value at T = 0, the one we want. This step is called interpolation. Before any of this, two standard steps tidy the formula: sparsification cuts it into pieces with few clauses each, and a copying trick makes every variable appear in at most three clauses. That is what lets the groups stay small.

The result, for any fixed clause width, is a deterministic algorithm that uses polynomial memory and runs in about 2n·log log n/√log n steps. The exponent grows more slowly than any cn, so ETH is false. So is the Strong Exponential Time Hypothesis, which implies it.

Why nothing gets faster

“Subexponential” is a statement about what happens as n goes to infinity. The proofs hide a constant C in that exponent, and nobody has pinned it down. Fabio Dias and Yvens Lima worked out where the new bound would actually beat brute force.

With C = 2 the new method wins only once a formula has about 1032 variables. With C = 10, it needs 103517. When Dias and Lima traced the actual constants in OpenAI’s tensor-contraction proof, they found no gain over brute force for any input of bounded density that could ever be written down. Practical SAT solvers, which handle millions of variables on real problems, are untouched.

What it does and does not mean

It does mean that many results of the form “this needs exponential time, assuming ETH” lose their footing. Researchers are moving to weaker assumptions. An MIT group points out that a 1990 hypothesis of Stearns and Hunt, equivalent to a “weak ETH”, still looks safe and supports most of the same arguments.

It does not mean P = NP: 2n/√log n is still enormously more than any polynomial. And as Lance Fortnow notes, it gives nothing new for problems like Subset Sum or the Traveling Salesman, because turning them into 3-SAT adds too many variables.

It may be remembered for one more reason. The core argument was found by AI models, at OpenAI and, independently, at Anthropic. Anthropic’s paper describes the two results as independent and concurrent, and early reports put both discoveries on the same day, 16 October; the papers themselves are dated a little later. People then checked it, simplified it and stress-tested it. Both proofs were also checked in the Lean proof assistant. That check confirms the formal proof is valid, but not that the formal statement matches the paper. Human reviewers have to confirm that part.
